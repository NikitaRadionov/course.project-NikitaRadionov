# ADR-001: Единый формат ошибок (RFC 7807)

Дата: 2025-09-22
Статус: Accepted

## Context

В проекте используются разные источники ошибок: HTTPException (от FastAPI), собственные исключения ApiError и ошибки валидации. Без унификации структура ответов на ошибки может отличаться, что усложняет отладку, мониторинг и работу клиентов.
Необходимо ввести единый JSON-формат ошибок, соответствующий принципам RFC 7807 (Problem Details for HTTP APIs).

## Decision

Принят формат, совместимый с RFC 7807:

{
  "type": "about:blank",
  "title": "<short_code_or_http_title>",
  "status": <http_status>,
  "detail": "<human_readable_message>",
  "correlation_id": "<uuid>"
}


Все ошибки возвращаются через глобальные обработчики
@app.exception_handler(ApiError) и @app.exception_handler(HTTPException).

Для внутренних ошибок (500) детали маскируются (detail = "internal_error").

correlation_id генерируется для трассировки (можно расширить через middleware).

Для контрактных тестов добавлен tests/test_errors.py::test_rfc7807_contract.

## Consequences

Плюсы:
- Унифицированный формат для логов, клиентов и тестов.
- Упрощение трассировки инцидентов по correlation_id.

Минусы:

- Небольшие накладные расходы на сериализацию и логику маскирования.
- Требуется дисциплина: только ApiError и HTTPException.

## Alternatives

1. **Возвращать ошибки в произвольном формате (`{"error": "message"}`)**
   - + Просто реализовать
   - − Неунифицированный формат, сложнее поддерживать мониторинг и контрактные тесты

2. **Использовать собственную структуру (`{"error": {"code": ..., "msg": ...}}`)**
   - + Гибкость
   - − Не соответствует стандарту RFC 7807, хуже совместимость с клиентами

3. **RFC 7807 (выбранное решение)**
   - + Стандартный формат, поддерживаемый многими SDK
   - + Удобен для интеграции с API Gateway и observability-инструментами
   - − Требует адаптации текущих exception-handler'ов

## Security impact

- Маскирование внутренних ошибок (500) предотвращает утечку стек-трейсов и данных окружения.
- `correlation_id` позволяет отслеживать инциденты без раскрытия деталей клиенту.
- Риск: если обработчик не перехватит исключение, стек может утечь через FastAPI по умолчанию.
  → Мера: глобальный handler для `Exception` и unit-тест `test_internal_error_masked`.
