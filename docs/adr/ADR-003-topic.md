# ADR-003: Управление секретами и конфигурацией
Дата: 2025-09-22
Статус: Accepted

## Context
необходимо обеспечить безопасное хранение конфигурации и подготовить инфраструктуру для будущего масштабирования.

## Decision
Путь к SQLite базе данных: через переменную окружения DATABASE_PATH (по умолчанию: ./app.db)

Запретить хранение любых чувствительных данных в коде и логах

Реализовать маскирование чувствительной информации в логах

Для будущего: подготовить структуру для миграции на внешнее хранилище секретов

## Alternatives
Хранение в конфигурационных файлах - отвергнуто из-за риска случайного коммита в репозиторий
Использование секрет-менеджера на текущем этапе - избыточно для текущих потребностей
Оставить хардкод в коде - нарушает принципы безопасности и DevOps practices

## Security impact
Снижение рисков: Устранение секретов из кода уменьшает вероятность утечки через Git
Соответствие стандартам: Выполнение требований OWASP ASVS по управлению секретами
Аудит: Маскирование в логах помогает соблюдать GDPR и требования по защите персональных данных

## Rollout plan / Definition of Done
Вынести DATABASE_PATH в переменные окружения

Провести ревью кода на соответствие новым правилам
