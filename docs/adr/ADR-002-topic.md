# ADR-002: Rate Limiting для защиты эндпоинтов
Дата: 2025-09-22
Статус: Accepted

## Context
Эндпоинты аутентификации и API подвержены DDoS и брутфорс-атакам. Без ограничения частоты запросов злоумышленники могут перегрузить систему или подобрать учетные данные пользователей. Требуется баланс между безопасностью и доступностью для легитимных пользователей.

## Decision
Внедрить rate limiting на уровне приложения для критических эндпоинтов:

/token (аутентификация): максимум 5 попыток в минуту с одного IP

/users (регистрация): максимум 3 запроса в минуту с одного IP

/media: максимум 100 запросов в минуту с одного IP

Общий лимит: 1000 запросов в час с одного IP

Использовать алгоритм "скользящее окно" через slowapi. При превышении лимита возвращать ошибку 429 Too Many Requests с деталями в формате RFC 7807.

## Alternatives
1. Без rate limiting - отвергнуто из-за высоких рисков безопасности
2. На уровне Nginx - отвергнуто, т.к. требует инфраструктурных изменений
3. По пользователям, а не IP - отвергнуто, т.к. до аутентификации пользователь неизвестен

## Security impact
Снижение рисков: Защита от R1 (подделка запросов), R9 (DDoS)
Соответствие: OWASP API Security Top 10 (API8:2023)
Баланс: Лимиты выбраны для блокировки атак без влияния на нормальное использование


## Consequences
Плюсы:
Защита от DDoS и брутфорс атак
Обеспечение доступности для легитимных пользователей
Соответствие best practices безопасности API

Минусы:
Дополнительная нагрузка на инфраструктуру
Возможные ложные срабатывания для пользователей за NAT
Необходимость мониторинга и тонкой настройки лимитов
